## 二、本轮（全面优化）修掉的真实缺陷

1. **泛词主导打分** → 引入 IDF
   「利」「害」各命中 5000+ 单元，与「乞骸骨」（几十单元）同权，
   精确率完全靠公式兜底。改为 Σ IDF(词) 后，稀有词权重 9.8 / 泛词 1.3
   （约 7 倍差）。平均并列选项数 3.36 → 3.92。

2. **规律启发是手写的** → 改为语料统计（最重要的诚实性修复）
   旧版把写死的格言标成「史书上反复出现的结构性倾向」，是未经测量的断言。
   现由 `derive_patterns.py` 从每个内核 top-40 案例导出，输出分两层：
   - ① 语料统计（可复核，附 n 与抽样出处）
   - ② 编者按（人的判断，明确自报家门）

   实测片段（谏诤内核，40 例）：文本出现「进言未被采纳」信号 **85.0%**，
   出现「被采纳」仅 **5.0%**；95% 含多方案争执。
   ⚠ 输出中同时附必读提醒：被拒率高部分反映史书取材偏好
   （「不听劝而败亡」比「听劝而平安」更有戏剧性），不是历史事实。

3. **隐性代价是固定查找表** → 改为按案例文本推导
   旧版同一内核所有案例输出完全相同（看似定制，实为模板）。
   现按案例文本是否出现线索词触发，**并附触发词供核对**，
   例如「信任折损（触发「疏」）」。

4. **碎片重复计分**（两个 bug）
   - 「撕破脸」同时命中 modern(3.0) 与「撕破」stem(1.0) → 同一信号算两遍
   - 「撕破脸/撕破/撕」三条互为子串 → 同一信号算三遍
   修法：把 modern 与 stems 放进同一场，按长度降序只保留「极大串」。

5. **「还」过度触发**
   「还」在 faith-or-interest 词表里，但「还有/还是/还要」遍地都是，
   造成大量误判。已移除单字「还」，改为「还钱/还债/还人情」。

6. **残留占位符与错位单元**
   剔除 9 条含 `[todo]` 的占位单元与单条即错位者（15,825 → 15,816）。

7. **审计工具自身的 3 个 bug**（教训：审计必须先自证）
   - 漏剥文件标题行 → 奇偶错位 → 误报「293/294 卷异常」
   - 单点指纹被源文件换行截断 → 误报引用保真仅 90.5%
   - 两处 `hit += 1` 并存 → C1 命中率算成 194%

8. **正则漏「零」字 → 18 卷静默丢失**（上一轮修复，记录在此）
   `第一百零一～一百零九卷`的「零」不在字符集内 → 整卷跳过。
   覆盖 274 → 292 卷。**静默丢数据最难发现：无报错，只是检索变弱。**

9. **场景词表不能自上而下设计**
   12 个内核按想象设计，第一次真实提问（负债低谷）返回完全无关结果。
   词表必须用**真实问法**验证。本轮据此把命中率从 72.5% 提到 98.0%。

## 三、已知短板（仍未修）

### P1　5 个内核候选泛化（IDF 缓解但未根治）
```
risk-return      81.1%      timing          79.1%
faith-or-interest 63.7%     family-wealth   63.4%
war-or-peace      59.1%     （对照：choose-side 9.2%）
```
IDF 让打分不再被泛词主导，但**候选集本身仍未收窄**。
根治需把泛词从 classical 表降级为「仅辅证词」。

### P1　测试集仍非独立
51 条问法与标注均由我撰写 → 98.0% 是**上界**，不是泛化性能。
真正的独立验证需要外部标注（用户提供或从真实提问收集）。

### P2　选项抽取噪声
「（承前）」占比偏高；会话性短句也被列为选项。
需加实质提案过滤器（须含动作动词或条件结构）。

### P2　人名实体索引（评估后主动放弃）
抽了 100 个候选人名，精度约 50%（「太史公/太后/大怒/发兵」混入）。
且用户提问是现代处境，很少输入历史人名，`--keywords` 已够用。
**结论：不发半准的功能。** 若日后要做，需多动词共现过滤。

## 六、定位

- 作为**案例检索器 + 证据展示器**：可用（引用保真 100%，亚秒查询）
- 作为**洞察生成器**：统计层已诚实化（可复核），但统计只描述本库文本，

### 本轮执行教训（比技术问题更值得记）

我用 `terminal` + heredoc 修改 Python 源码，**同一个坑踩了 7 次**：
heredoc 吃掉一层反斜杠，导致 `"\n".join` 被写成真换行、`"""` 被吃成 `'"\"\"\"'`、
正则里的 `\)` 变成未闭合字符串……每次都要再花几轮修复。
**正确做法：第一次 SyntaxError 出现时就该切换到 write_file 写补丁脚本。**
下一次改多行/含转义的 Python，直接 write_file，不要试 heredoc。
